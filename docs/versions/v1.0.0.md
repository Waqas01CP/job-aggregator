# Version 1.0.0

**Version 1.0.0 is the aggregator working for the operator himself, as he intends it.** Making it work for anyone else is a later version, and a decision of its own. Defined by the operator on 2026-10-04 (2026-10-03 UTC) and decided in ADR-0059.

This file is distinct from the decision records on purpose. A decision record is concluded once and then only amended. A version is a target the project moves toward, so its status changes as the work does. The decisions stay in ADR-0059; this file says where each of them stands. It is the operator's decision of 2026-10-05 (2026-10-04 UTC) that the end state live in a file of its own, named for its version.

**How it is kept.** The architecture chat updates a status when a seat's report shows it changed, with a row in Changes. The implementing seat may correct a status that is factually wrong, as ADR-RULES lets it annotate a stale fact. A change to what 1.0.0 includes, or to its test, is a decision: it is made with the operator and recorded in ADR-0059 first.

**Statuses used:** Built, Not built, Measuring, To confirm (a seat checks what the code does), Not set (the operator's to choose), Waiting, Out.

## What 1.0.0 is for

The operator should see every job he can take, and no job he cannot, as soon as it is posted, from sources worth his time, without the system needing him to watch it.

The pieces already serving that are recorded in their own decisions and described in `CAPABILITIES.md`: two runs a day (ADR-0006), eligibility (ADR-0057), the description's three facts (ADR-0058), age judged at first sight (ADR-0052), the classification flow (ADR-0050), clearing the display (ADR-0055), the private stores (ADR-0047, ADR-0051) and the contract check (ADR-0018, ADR-0061).

## The test for done

Proposed by the architecture chat and accepted by the operator on 2026-10-05 (2026-10-04 UTC). Only he declares 1.0.0 done.

| Requirement | Status |
|---|---|
| Measure A (ADR-0015) holds: publication to first appearance, median at or under 24 hours, 90th percentile at or under 72 | Not set: the window over which it must hold is his to choose |
| Nothing is lost silently: every drop and every closure names its rule | Built, with one limit for him to judge: every run logs its drops per rule per board, and every removal from the display is stored with its reason; a dropped posting's own reason is not stored, and is recomputable from the raw layer |
| Every scheduled run happens (ADR-0054) | Built. Measured from 2026-09-17 to 2026-10-04: 36 of 36 fetch slots and 10 of 10 contract slots ran, each 3.3 to 7.9 hours after its cron; two fetch runs failed, on 2026-09-17 and 2026-09-27 |
| Every failure reaches Airtable | Built. Contract findings live: the `Health` table's first 17 rows, all findings, written by the fetch of 2026-10-08T19:13Z (ADR-0061). A fetch-run failure's row is held by tests and not yet seen live. One limit: a contract check that crashes before any platform or at its commit writes no log, so no row, and shows only as a failed run |
| Every integrated source has its own contract check, isolated from the rest | Built, 2026-10-04 (ADR-0061), and held by a fitness function: no platform is built without its check |
| He uses the tables for a period | Not set: the period is his to choose |

**How later versions are numbered is not decided.** The operator has called the star's version "v2". Under semantic versioning, the most common convention for three-part numbers like 1.0.0, an addition that changes nothing existing is a minor version, 1.1.0, and 2.0.0 marks a change that breaks what came before. Which convention he wants is his call when the next version is defined.
