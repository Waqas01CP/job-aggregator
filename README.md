# job-aggregator

A scheduled pipeline that polls employer applicant-tracking-system job boards, deduplicates and filters the results against fixed rules, and writes what survives to a table for review.

**Status: design, not built.** The documentation describes a system that does not exist yet. No code has been written.

## What this repository stores

Job posting **metadata only**: employer, title, location, ATS platform, publication date, first-seen date, stated experience, canonical URL, and the filter verdict with the rule that produced it.

## What it does not store

**Job description text, in any form.** No descriptions, no snippets, no raw HTML, no recorded API payloads containing description text. Test fixtures have description fields stripped before they are committed, and a pre-commit guard rejects any that are not.

This is a deliberate boundary, recorded in ADR-0011. Metadata is factual record-keeping. Employer-authored description text belongs to the employer, and republishing it is a different act from reading a public endpoint.

## What it does not do

No relevance scoring, ranking, or model-based classification of postings. Every posting is admitted or dropped by a deterministic rule that can be named. Reasoning in ADR-0010.

No user interface. No notification system. No paid data acquisition.

## Setup

One command per clone, and nothing else:

```
git config core.hooksPath .githooks
python tools/generate_map.py
```

The hook blocks a commit that stages a raw payload, an unsanitised test fixture, or a stale `MAP.md`. `MAP.md` is generated by `tools/generate_map.py` and must never be edited by hand; to change a row, edit that file's frontmatter and regenerate.

`docs/architecture.md` is a superseded design kept as a record of what was rejected. It carries a banner saying so. Do not implement from it.
